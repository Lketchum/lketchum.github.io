把 MATLAB 原型迁移到 C#，目标不应只是“得到相似画面”。真正有价值的是把隐含的数组和显示约定拆成清晰职责，并建立能在以后重构时持续运行的验证证据。

<!-- more -->

## 背景

MATLAB 适合快速读取矩阵、调整参数和观察切片；C# .NET 8 WPF 更适合承载桌面交互、类型边界和自动化测试。两者不是替代关系：CT3D 用 MATLAB 暴露算法过程，用 C# 验证工程分层。

当前 C# 已有 DICOM 序列读取、HU、正交 MPR、Slab mean/MIP、绕 X oblique 与三线性采样，并有 29 个自动化测试。测试数量本身不是质量结论，因此还需要说明 fixture、风险点和断言内容。

## 原理

迁移中的核心是把“同一件事”拆成可比较的纯计算阶段：

`输入元数据 → 像素解释 → HU 体 → 几何采样 → 投影/聚合 → 显示映射`

如果 DICOM 读取、插值和 WPF 位图写入混在一个事件处理器里，结果差异只能通过界面猜测。相反，纯函数或窄接口允许使用小型内存数据测试 HU、MPR 与插值，不必每次启动 UI 或依赖完整数据集。

跨实现验证不是要求两个环境每个字节天然相同，而是先统一：

- 输入数据与排序；
- 维度和坐标约定；
- spacing、角度及输出尺寸；
- 边界和取整规则；
- 窗宽窗位参数；
- 浮点比较容差。

统一这些条件后，差异才有诊断价值。

## 实现映射

CT3D 的职责可以按以下层次理解：

1. **DICOM 输入层**：识别当前支持的单帧、8/16-bit 单色、非压缩数据，读取序列所需元数据和像素。
2. **领域数据层**：保存 HU 体、尺寸与 spacing，不依赖 WPF 控件。
3. **算法层**：实现正交 MPR、绕 X oblique、三线性插值、Slab mean/MIP。
4. **显示映射层**：执行窗宽窗位与输出像素转换。
5. **WPF 展示层**：组织交互、参数和视图刷新，不承担 DICOM 数值语义。
6. **测试层**：用可预测数据覆盖关键转换和退化关系。

MATLAB 一侧已有 DICOM→HU、窗宽窗位、三平面 MPR、斜切教学，以及等值面/`volshow` 集成。跨实现对照只比较双方都实现、且参数可对齐的部分；不能用 MATLAB 的可视化集成暗示 C# 已有 3D 网格或体绘制。

## 验证方法

### 单元级

- 使用已知 slope/intercept 验证 HU；
- 使用递增坐标体检查三个正交方向；
- 验证整数坐标和体素中心处的三线性结果；
- 验证 Slab 厚度退化到单层时的行为；
- 分别检查 mean、MIP 与越界策略。

### 跨实现

把同一个小体数据或合法 DICOM 输入送入 MATLAB 与 C#，输出中间结果而不只截图。优先比较：

1. 体尺寸、spacing 和若干 HU 点；
2. 三个正交切片的方向与关键像素；
3. 固定角度 oblique 的采样点；
4. 相同 slab 参数下的聚合结果。

若结果不一致，按“输入解释 → 坐标/维度 → spacing → 插值 → 边界 → 显示映射”的顺序缩小范围。

### 回归与性能

项目已经加入共享的 `3 × 3 × 3` 合成体 Golden Fixture，固定三种正交切面、30° 斜切与 `1e-4` 容差；MATLAB 验证脚本与 C# 测试读取同一份数据。性能方面提供独立 Benchmark 控制台，固定合成体、输出尺寸和迭代次数，输出 axial、oblique 与 slab 的平均耗时。正式发布性能数字前仍需补充 CPU、构建配置和运行环境。

## 限制

- 现有 29 个测试不等于覆盖所有 DICOM 变体、方向矩阵和异常输入。
- WPF 可正确显示 2D 重切结果，不代表已有 C# 原生体绘制。
- C# 当前没有原生 VTK、Marching Cubes 或 3D 网格。
- MATLAB 与 C# 的默认数组和显示习惯不同，截图相似不能替代中间数值比较。
- 项目是学习与工程验证用途，不是临床软件验证结论。

## 面试表述

可以这样回答：

> 迁移时我没有逐句翻译 MATLAB，而是按 DICOM 输入、HU 领域数据、几何采样、显示映射和 WPF 展示拆层。算法层可以脱离 UI 测试，目前 C# 有 29 个测试，并通过共享 Golden Fixture 与 MATLAB 对照三种正交切面和 30° 斜切。这样既能利用 MATLAB 快速验证，也不会把 MATLAB 的 volshow 或等值面能力误说成 C# 已实现。
