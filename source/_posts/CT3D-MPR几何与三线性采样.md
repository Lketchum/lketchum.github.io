MPR（多平面重建）不生成新的 CT 信息，而是从已有三维体数据中按指定平面重新取样。正交切片可以用数组索引快速验证；一旦平面发生旋转，就必须明确坐标、spacing、反向映射和插值。

<!-- more -->

## 背景

CT3D 先在 MATLAB 中完成三平面 MPR 和斜切教学，再把核心路径迁移到 C# .NET 8 WPF。迁移的难点不在语法，而在于两种环境可能使用不同的数组维度顺序、坐标起点、图像行列定义和显示方向。

如果这些约定没有先写清楚，常见现象包括图像翻转、旋转方向相反、非等距数据形变，以及边界出现异常条带。

## 原理

### 平面参数化

可把输出平面上的点写成：

`P(u, v) = O + uU + vV`

其中 `O` 是平面原点，`U`、`V` 是平面内两个基向量，法向量由二者叉积得到。每个输出像素对应一个物理空间点，再转换到体数据索引坐标。

正交 MPR 是这套表达的特例：输出平面与体数据某两个轴平行，采样点通常落在整数索引上。Oblique 的采样点大多位于体素之间，需要插值。

### Spacing 与反向映射

旋转应建立在物理空间语义上。若体素 spacing 为 `(sx, sy, sz)`，不能直接把三个索引轴看成等长。输出像素先落到物理空间，再除以对应 spacing 转为连续索引，才能避免非等距体数据被错误拉伸。

重采样通常采用反向映射：遍历输出像素，计算它在输入体中的位置。这样每个输出像素都有确定来源，不会像正向投影那样留下空洞。

### 三线性插值

连续坐标 `(x, y, z)` 位于相邻八个体素构成的立方体中。三线性插值先沿一个轴线性混合，再沿第二、第三轴混合。它比最近邻平滑，同时仍能用确定性小体数据手工验证。

边界不是附属细节：当八邻域不完整时，必须决定拒绝、截断、夹取还是使用背景值，并让 MATLAB 与 C# 对照时采用同一规则。

## 实现映射

MATLAB 线已有三平面 MPR 与斜切教学，适合验证矩阵、切片方向和旋转几何。C# 线已有：

- 轴向、冠状、矢状正交 MPR；
- 绕 X 轴的 oblique；
- 三线性采样；
- WPF 显示承载。

当前 C# 的“绕 X 轴”是明确边界，不应描述成任意法向、任意姿态的通用重切。实现上应把“输出网格生成”“坐标变换”“体数据采样”“窗宽窗位”和“WPF 像素输出”分开，这样翻转或数值差异能定位到具体阶段。

从 MATLAB 迁移时，建议先对齐以下约定：

1. 三个数组维度分别表示什么；
2. 输入原点和输出平面中心如何定义；
3. 正角度的旋转方向；
4. spacing 在变换前后何时应用；
5. 越界值和显示灰度如何处理。

## 验证方法

- **坐标体**：构造体素值与坐标有简单关系的小体数据，切片内容可直接预测。
- **零角度退化**：oblique 角度为 0 时，应与对应正交 MPR 在既定容差内一致。
- **整数点采样**：连续坐标恰好落在整数体素时，三线性结果应等于该体素值。
- **中心点采样**：在规则八邻域中心检查权重之和与手算平均结果。
- **跨实现对照**：固定原点、角度、输出尺寸、spacing、窗宽窗位和边界规则，比较 MATLAB/C# 的关键像素或矩阵。
- **方向标记**：使用非对称测试体，避免对称图案掩盖翻转和轴交换。

仓库已提供独立 Benchmark 控制台，固定合成体、输出平面、角度和迭代次数，分别测量 axial、oblique 与 slab。对外记录结果时还必须补充 Release 构建配置和硬件环境，避免把单机采样值误写成通用性能结论。

## 限制

- C# 当前 oblique 只覆盖绕 X 轴，不代表通用任意平面重建。
- 三线性插值会平滑高频细节；它是工程选择，不等于唯一正确的重建滤波方案。
- 当前工作建立在已读取的体数据上，与 FBP/DBT 从投影生成体数据的重建任务不同。
- 视图方向还需结合明确的坐标约定验证，不能只凭“看起来方向正常”。

## 面试表述

可以这样表述：

> 我把 MPR 定义为从输出平面到输入体的反向采样问题。正交 MPR 是整数索引特例，斜切则先在物理空间建立平面，再结合 spacing 转回连续索引，并用三线性插值取值。我用零角度退化、可预测小体和 MATLAB/C# 跨实现结果验证坐标约定。当前 C# 明确只实现绕 X 轴 oblique，没有把它夸大为任意姿态重切。
